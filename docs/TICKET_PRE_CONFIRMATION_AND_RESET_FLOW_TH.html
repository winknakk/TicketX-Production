1. ที่มาและปัญหาเดิม (Background & Problem Statement)

❌ ปัญหาของระบบเดิม (Immediate Creation)
  • เปิดตั๋วทันทีในข้อความแรก: บอทเรียก create_ticket ทันทีที่ลูกค้าพิมพ์ข้อความแรกเข้ามา
  • เกิดปัญหาตั๋วขยะ (Junk Tickets): หากลูกค้าพิมพ์ผิด, แจ้งระบบผิด, หรือแก้ไขปัญหาได้เองแล้ว ตั๋วจะถูกส่งไปยัง Plane.so ทันที

  • รองรับการแก้ไข & รีเซ็ต: หากลูกค้าพิมพ์แก้ หรือขอยกเลิก บอทสามารถปรับปรุงข้อมูลหรือยกเลิกได้โดยไม่สร้างตั๋วขยะ

5. การตั้งค่า Prompt สำหรับ Gatekeeper Agent (E.D.I.T.H.)

# TWO-STEP TICKET CONFIRMATION & RESET RULES

1. NEW INCIDENT INTAKE:
   - When customer reports a new bug/outage/issue AND no pending confirmation in history:
   - Output ticket_action: "CONFIRM_REQUIRED"
   - Extract subject, summary, priority, severity
   - The system will summarize and ask the customer to confirm.

2. CUSTOMER CONFIRMATION:
   - When previous message asked for confirmation AND customer says "ยืนยัน", "ถูกต้อง", "ใช่ค่ะ", "โอเค":
   - Output ticket_action: "CREATE"
   - Output targetAgent: "support"
   - Pass accumulated subject and summary to create the ticket.

3. CUSTOMER CORRECTION:
   - When customer modifies details ("ไม่ใช่ค่ะ", "ขอแก้เป็น..."):
   - Output ticket_action: "CONFIRM_REQUIRED" with updated summary.

4. CUSTOMER CANCELLATION / RESET:
   - When customer says "ยกเลิก", "ไม่แจ้งแล้ว", "แก้ได้แล้ว", "รีเซ็ต":
   - Output ticket_action: "NONE"
   - Output intent: "CANCEL_RESET"
   - Set reply_text to polite cancellation response.
